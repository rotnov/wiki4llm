01 / The mechanism

From tracked files
to useful context.

A repeatable path from the documentation your team maintains to the sources an agent can retrieve.

01

Select the knowledge

Choose the Git-tracked files each collection should include. Include patterns, exclusions and file types define the scope. Connecting a repository does not mean indexing every file.

02

Index the changes

The indexer compares content and processing settings with durable state. It uploads new or changed files and reuses unchanged versions.

03

Publish a complete update

A new publication becomes active after the selected files finish indexing and source checks pass. A failure before publication preserves the previous active snapshot.

04

Retrieve the source

An agent uses query to find relevant content and get to read a returned reference. Results carry repository, document and revision provenance.

02 / The boundaries

Organize sources.
Scope access.

Authentication establishes who is asking. Reader grants determine which workspaces that identity may access.

WORKSPACEReader grants

One workspace, multiple collections.
Access is granted at the workspace boundary.

Workspaces define access. Each groups collections under reader grants and a shared publication lifecycle.

Collections organize sources. Separate collections preserve source identities, even when files have the same name.

03 / The operating model

One workflow.
A durable memory of the work.

Reuse the same GitHub Actions indexing workflow across repositories, with explicit configuration and separate credentials.

START SMALL

Preview. Verify. Automate.

Begin with a manual preview. Run indexing and retrieval checks. Then enable automatic updates on approved branch pushes. Each run synchronizes the whole configured workspace.

KEEP THE STATE

Temporary runner, durable journal.

The remote authority keeps ownership, publication state and coordination between publishers. Subsequent runs can reconcile interrupted work. Runner caches and build artifacts are not the state authority.

04 / The agent interface

Find it. Read it.
Know where it came from.

The gateway checks reader permissions and active-file membership before returning content. Ingestion and retrieval use separate credentials; MCP reads do not edit your Git sources.
